# HUB_Optimus Operator infrastructure candidate

Status: **LOCAL v0.4 / NOT DEPLOYED / AWS AND PUBLIC NO-GO**
Prepared: 2026-08-26

The candidate defines a bounded authenticated implementation of
`POST /intake/url`. It has not changed AWS account `904851777129`, DNS,
`api.huboptimus.dev`, GitHub Pages, or the live Operator.

## Closed locally

- Account and region are fixed to `904851777129` and `eu-west-1`.
- Activation is split into mandatory `foundation`, `controls`, and `private`
  phases; only `private` creates the API route/stage and concurrency `1`.
- Public signup is rejected; private smoke permits only the invited MFA user
  whose Cognito subject matches a mandatory protected SHA-256 allowlist.
- Cognito uses authorization code + S256 PKCE, exact `operator/intake` scope,
  short tokens, no client secret, and no direct password/SRP/custom flow.
- API Gateway and Lambda independently validate access-token client and scope.
- SSRF controls include IPv4/IPv6 special ranges, all-answer DNS validation,
  numeric-address pinning, fresh sockets, peer verification, redirect
  revalidation, HTTPS downgrade blocking, and bounded responses.
- Among cost controls, foundation creates only the gross-account budget;
  controls adds the tagged workload budget and anomaly monitor after the tag
  is active, plus an operational SNS email subscription that must be confirmed.
  Foundation also creates the disabled tagged workload resources.
- Separate prepare/execute role names, account, region, clean tree, exact SHA,
  and active cost tag have phased read-only predeploy checks with no role-name override;
  private also requires an immediate window no longer than two hours.
- CDK feature flags are explicitly pinned to current recommendations.
- The Lambda asset contains the pinned DynamoDB SDK and is generated by pinned
  esbuild; a byte comparison rejects stale output and synthesis fails if it is
  missing. The deployment session is narrowed to one object, requires S3 bucket
  versioning, injects the immutable `S3ObjectVersion`, and verifies both the
  upload checksum and final Lambda `CodeSha256`.
- The entire approved window has a three-attempt ceiling, including malformed
  authenticated requests. Its anonymous key is derived from the reviewed
  start/expiry values, so crossing UTC midnight cannot renew the quota; no
  subject identifier is stored.
- The private template adds a dedicated Scheduler group, one-time target,
  single-purpose role, encrypted four-day DLQ, and three failure alarms. The
  target sets Lambda reserved concurrency to `0`; handler expiry is independent.
- The candidate workflow fixes account, region, roles, repository, branch,
  signup and provenance; Prepare cannot execute, Execute cannot prepare, and a
  third stop-only role can only set the fixed Lambda concurrency to zero.
- CloudFormation's change-set template, exact resource-action delta, parameters
  HMAC fingerprint, non-secret subject/window binding, and source SHA are rechecked
  after the second Environment approval. `deactivate` is tied to the private
  stack's `SourceCommit` and reconciles it to controls.
- The companion browser integration defaults disabled, uses PKCE S256 and an
  in-memory Bearer token, and never caches runtime enablement or OAuth callback
  query values.
